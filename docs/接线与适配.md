# rom-watch 接线与适配（换板子 / 换屏 / 换数据源怎么改）

> 这份文档解决三件事：**①线怎么接**（ESP8266 ↔ OLED / 串口屏 / 按键 / LED）· **②接好了怎么验**（自检端点）· **③要换硬件时改哪里**（**只改 `config.h`**，主文件一个字不用动）。
> 默认板型 **WeMos D1 mini**（ESP-12F / 4MB），固件版本 **1.0.0**。
> 口径与 `README.md`、`开关与配置说明_rom-watch.md` 一致；**有冲突以源码 `rom-watch.ino` / `config.h` 为准**。

---

## 1. 接线表

### 1.1 ESP8266 ↔ 0.96" OLED（I2C，4 线）

| OLED 模块 | D1 mini | 对应宏 | 说明 |
|---|---|---|---|
| **GND** | **GND** | — | ★共地，必须接 |
| **VCC** | **3V3** | — | ⚠️ **别接 5V**（SSD1306 模块多数只吃 3.3V） |
| **SDA** | **D2** | `PIN_OLED_SDA` | I2C 数据（默认 `D2`） |
| **SCL** | **D1** | `PIN_OLED_SCL` | I2C 时钟（默认 `D1`） |

- 地址默认 **`0x3C`**（宏 `OLED_ADDR`）。少数模块是 **`0x3D`** —— 扫不到时先换这个值试。
- 分辨率默认 **128×64**（0.96"）。0.91" 那种 **128×32** 小屏要把 `OLED_SMALL` 设成 `1`，版面会自动换成两行。
- 固件在 `setup()` 里就 `Wire.begin(PIN_OLED_SDA, PIN_OLED_SCL)`（`rom-watch.ino:2323`）并 `oled.init()`（`:2326`）⇒ **连 WiFi 之前屏上就能看到自检页**。

### 1.2 ESP8266 ↔ TJC 串口屏（软串口，4 线）

| 屏（TJC 系列） | D1 mini | 对应宏 | 说明 |
|---|---|---|---|
| **VCC** | **独立 5V 电源正极** | — | ⚠️ 屏约 **420mA @5V** —— **不要从板子取电**，带不动 |
| **GND** | **GND** | — | ★**必须共地**；不共地串口一定不通 |
| **TX** | **D5**（板的 RX） | `PIN_TJC_RX` | 默认 `D5`（= GPIO14） |
| **RX** | **D7**（板的 TX） | `PIN_TJC_TX` | 默认 `D7`（= GPIO13） |

**四条硬规矩：**

1. **TX / RX 必须交叉**：屏 TX → 板 D5，屏 RX → 板 D7。「TX 对 TX」是最常见的接错。
2. ★ **屏的任何一根线都不要接 D6**（详见第 2 节）。
3. **屏的地、板子的地、5V 电源的地 —— 三者必须连一起**。
4. **波特率**：固件开机**自动探测**（依次试 `115200 / 9600 / 19200 / 57600 / 38400 / 230400`，`rom-watch.ino:2254`），
   探到就把 `tjcBaud` 记下来；全都不回话则回退到 **115200**（`:2273`）。

**电平**：TJC 的通讯口一般是 **3.3V**，与 ESP8266 直连即可，**不需要电平转换**；串了 1kΩ 限流电阻可以留着，不影响通信。

### 1.3 按键（板载 FLASH 键）

| 项目 | 值 | 说明 |
|---|---|---|
| 引脚 | **D3** | 宏 `PIN_BTN`，默认 `D3`（= GPIO0）；`INPUT_PULLUP`（`rom-watch.ino:2320`）⇒ **按下为低** |
| 手势 | 短按（40ms~1.5s） | **我已刷**（推进水位线，等同网页 `/ack`） |
| 手势 | 按住 1.5~3 秒松手 | **跳过这版**（等同网页 `/skip`） |
| 手势 | 按住 ≥ 3 秒 | **请求下载**（★唯一的下载触发方式；已去掉「双击」防误触） |

> ⚠️ 板上那个 **RST 键是硬复位**，按了就重启，**固件读不到**，不能当按钮用。

### 1.4 LED

| 项目 | 值 | 说明 |
|---|---|---|
| 引脚 | **`LED_BUILTIN`** | 宏 `PIN_LED`，默认板载 LED（= GPIO2） |
| 极性 | **低电平点亮** | `ledOn()` = `digitalWrite(LOW)`；`ledOff()` = `HIGH`（`rom-watch.ino:497`） |
| 正常 | **全灭** | 不闪 —— 「灯不要一直闪」是明确要求 |
| 有新版本 | **常亮** | 常亮报警，一眼看得见又不烦（`:2419`） |

> `/led?on=1|0|2` 可手动点灯 15 秒，用来把「**灯坏没坏**」和「**逻辑要不要亮**」一刀切开。

### 1.5 供电总则

| 部件 | 供电 | 说明 |
|---|---|---|
| 板子（D1 mini） | **USB 5V** 或 5V 脚 | 建议从 USB 供，稳定 |
| OLED | **3V3**（从板子取） | 电流很小，可从板子取 |
| TJC 串口屏 | **独立 5V**（★不从板子取） | 电流大；**必须与板子共地** |

> ⚠️ 三条地的原则：**屏的地 = 电源的地 = 板子的地**。少接一根，表现就是「屏一个字都不回」。

## 2. ★醒目警告：串口屏不要用 D6（GPIO12）

> ⚠️⚠️ **串口屏的 RX/TX 绝对不要接 D6（GPIO12）**。

- D6（GPIO12）是 ESP8266 **开机时判断 flash 电压**的脚。它被串口占着（或被驱动成输出）⇒ 板子可能**直接起不来**。
- 这个坑踩过两次，源码里留了记录：
  - `rom-watch.ino:154-155` —— 原来写 D6，改成 D7。
  - `rom-watch.ino:1903-1905` —— `/tjcwire` 体检端点原来打的是 D6，也改成了 D7。
- 默认接线（**D5 / D7**）已经避开它了，**改接线时别改回去**。

## 3. 适配层表（换硬件只改 `config.h`）

主文件里每个适配项都写成 `#ifndef`（`rom-watch.ino:67-93`）⇒ **你定义了才覆盖**，不写就走默认值，**主文件一个字不用动** ✓

| 宏 | 默认值 | 作用 | 什么时候改 |
|---|---|---|---|
| `PIN_OLED_SDA` | `D2` | I2C 数据脚 | 换 I2C 引脚 |
| `PIN_OLED_SCL` | `D1` | I2C 时钟脚 | 换 I2C 引脚 |
| `OLED_ADDR` | `0x3C` | OLED 的 I2C 地址 | 少数模块是 `0x3D`（扫不到就换） |
| `OLED_SMALL` | `0` | `0`=128×64；`1`=128×32（版面自动换成两行） | 用 0.91" 小屏时设 `1` |
| `PIN_TJC_RX` | `D5` | 屏 TX → 板（软串口 RX） | 换串口屏接线（★别用 D6） |
| `PIN_TJC_TX` | `D7` | 板 → 屏 RX（软串口 TX） | 换串口屏接线（★别用 D6） |
| `PIN_LED` | `LED_BUILTIN` | 报警灯脚 | 换板子 / 外接 LED |
| `PIN_BTN` | `D3` | 板载 FLASH 键 | 换板子 / 外接按键 |
| `OTA_PASSWORD` | 源码里的默认口令（见 `rom-watch.ino` 适配层） | OTA / `/update` 口令 | ★**分享/开源前务必改掉**；`/update` 用户名 `admin` |
| `DFLT_HOST` / `DFLT_PATH` | 空 | 第一次开机的默认数据源 | 想开机就有默认源（**留空合法**） |
| `DFLT_INTERVAL` | `600` | 轮询秒数（网页最小 60） | 想改默认轮询间隔 |
| `USE_TJC` / `USE_OLED` | `1` / `1` | 编译期功能开关（见第 5 节） | 不用屏/OLED 时关掉 |

### 3.1 怎么改（三步）

```bash
cd <仓库路径>/serial-screen/firmware/rom-watch
cp config.example.h config.h          # Windows: copy config.example.h config.h
# 然后编辑 config.h：取消注释、改成你的值
arduino-cli compile --fqbn esp8266:esp8266:d1_mini .
```

> ★★ **改接线只改 `config.h`** —— 不要把引脚写回 `rom-watch.ino`。
> 写回主文件有两个后果：① 开源/分享时你的私有值泄露；② 下次别人改 `config.h` 会「改了不生效」，排查被带偏。

> ⚠️ `config.h` 是你的私有文件（WiFi 密码、服务器地址），`.gitignore` 已排掉，**别手滑提交**。仓库里只有 `config.example.h` 样板。

## 4. 换板子 / 换屏 / 换数据源

### 4.1 换板子（换 FQBN）

```bash
set ROMWATCH_FQBN=esp8266:esp8266:nodemcuv2
python tools\build_matrix.py
```

- 环境变量 `ROMWATCH_FQBN` 覆盖板型（默认 `esp8266:esp8266:d1_mini`，见 `tools/build_matrix.py:45`）。
- 换板子后**引脚编号可能变**（NodeMCU 与 D1 mini 的丝印不同）⇒ 顺手核对第 3 节的适配层。

### 4.2 换屏

| 换成 | 要改 |
|---|---|
| 0.91" 小屏（128×32） | `#define OLED_SMALL 1` |
| 地址是 `0x3D` 的模块 | `#define OLED_ADDR 0x3D` |
| I2C 引脚不同 | `#define PIN_OLED_SDA ...` / `#define PIN_OLED_SCL ...` |
| 另一块 TJC 屏 | `#define PIN_TJC_RX ...` / `#define PIN_TJC_TX ...`（★别用 D6）；波特率不用改，开机自动探测 |
| 干脆不接屏 | `-DUSE_TJC=0` / `-DUSE_OLED=0` |

> 128×32 与 128×64 两套版面**编译期就分岔**（`OLED_H`，`rom-watch.ino:166`）⇒ 改完必须**重新编译烧录**，网页上改不了。

### 4.3 换数据源

数据源**不用改代码**，网页「监测设置」里就能换（`/cfg` 也是 POST 这条路）：

| 预设 | 服务器 | 路径 | 取值/时间键 | 方式 |
|---|---|---|---|---|
| `0` OpenList 目录（默认） | 你的服务器（如 `alist.example.com`） | 目录（如 `/你的目录/…`） | `name` / `created` | POST |
| `1` GitHub Release | `api.github.com` | `/repos/OWNER/REPO/releases/latest` | `tag_name` / `published_at` | GET |
| `2` 自定义 JSON | 自己填 | **就是请求路径本身** | 自己填 | GET/POST |

**两个必须记住的坑**：

1. **「请求路径」≠「要盯的目标」** —— OpenList 的请求路径**恒定**是 `/api/fs/list`，目录走 **POST body**。只有预设 `2` 才把「路径」当请求路径。
2. **GitHub 两条硬规矩**：必须带 `User-Agent`（不带直接 403）；未登录**限流 60 次/小时/IP** ⇒ 轮询别小于 10 分钟（默认 600 秒安全）。

### 4.4 一键命令与环境变量

| 环境变量 | 作用 | 例子 |
|---|---|---|
| `ROMWATCH_FQBN` | 覆盖编译板型 | `set ROMWATCH_FQBN=esp8266:esp8266:nodemcuv2` |
| `ROMWATCH_OTA_PASS` | 覆盖 OTA 口令 | `set ROMWATCH_OTA_PASS=你自己的口令` |
| `ROMWATCH_PORT` | 覆盖串口 | `set ROMWATCH_PORT=COM7` |

```powershell
cd <仓库路径>\serial-screen
python tools\ota.py push --sketch rom-watch     # 编译 + OTA 推 + 自动校验（日常就这条）
python tools\ota.py status                      # 看板子 /status
python tools\ota.py serial --sec 20             # 看串口日志
python tools\build_matrix.py                    # 多配置资源对比
```

## 5. 编译开关矩阵（六配置）

这块板子 **IRAM 只有 64KB，全开就到 96%** ⇒ 不用哪个就把哪个整块不编进来（`config.h` ① 节）。

| 配置 | 编译开关 | RAM | IRAM | Flash | bin |
|---|---|---|---|---|---|
| `full`（默认） | — | 39996 (49%) | 63475 (96%) | 637172 (60%) | 683040 B |
| `no_tjc` | `-DUSE_TJC=0` | 37400 (46%) | 61923 (94%) | 623260 (59%) | 665568 B |
| `no_oled` | `-DUSE_OLED=0` | 39784 (49%) | 63475 (96%) | 524764 (50%) | 570528 B |
| `minimal` | 两个都 0 | 37144 (46%) | 61923 (94%) | 510852 (48%) | 553008 B |
| `oled32` | `-DOLED_SMALL=1` | 39976 (49%) | 63475 (96%) | 636532 (60%) | 682384 B |
| **`portable`** | **干净副本（不带 `config.h`）** | 39820 (49%) | 63475 (96%) | 637060 (60%) | 682752 B |

> ⚠️ 上表是 2026-09-30 的**实测快照**（与 `开关与配置说明_rom-watch.md` 第 1 节同源）。
> **要当前数字请跑 `python tools\build_matrix.py`** —— 改了代码数字就会变，别拿旧表当结论。

**怎么读这张表（不吹）**：

- `USE_TJC=0` ⇒ **IRAM 只降 2 个点（−1552 B）**，flash 省 13 KB，RAM 省 2.5 KB。**它没「解决」IRAM 问题** —— 剩下那 94% 是 WiFi + BearSSL + WebServer + ArduinoOTA 这些**底座**，关不掉。
- `USE_OLED=0` ⇒ IRAM 一点不降（本来就不吃 IRAM），但 **flash 省 73 KB**（中文字模是大头）。
- ⇒ **结论**：IRAM 天花板就在 94~96% 之间。想再加功能只能靠：把字符串塞 PROGMEM、少用 `String` 拼接、必要时关 mDNS，或者**换 ESP32-C3**。别指望关开关能腾出空间。

**`portable` 那一行是「能开源」的实测证据**：脚本把 `rom-watch.ino` / `web_ui.h` / `cn_font.h` 三个可公开文件复制到临时目录、**故意不带 `config.h`** 编一遍 ⇒ 编过了 ⇒ 别人 clone 下来直接就能编译（`tools/build_matrix.py:62-70`）。

## 6. 接线排错对号入座

| 现象 | 先看这里 |
|---|---|
| **屏无应答 / 字段不变** | ① `/rom` 里 `tjcEn`（本固件有没有编屏）与 `tjcOk`（屏答没答话）② `/tjcwire`（**短接 D5–D7**）分清「板子/线的问题」和「屏的问题」③ `/tjcsweep` 试波特率 ④ 屏的 `sendxy` 每次上电会重置，固件开机自动重发 ⑤ 屏的 5V 与**共地** |
| **OLED 不亮** | ① `/i2c` 扫得到 `0x3C` 吗 ② 扫不到 ⇒ 接线（SDA/SCL 是否反了、共地）③ 扫得到但不亮 ⇒ 试 `OLED_ADDR 0x3D` ④ 确认 `USE_OLED=1` |
| **上电反复重启** | ① `/log` 看「上次跑到阶段」+ 启动次数（黑匣子存在 RTC 内存里，异常重启不丢）② 屏线是不是接到 **D6** 了（第 2 节）③ 屏是不是从板子取电（电流不够）④ `/rom` 看 `heap` 是不是见底 |
| **I2C 扫不到** | ① `/i2c` 的 `sda`/`scl` 字段是不是你实际接的脚（它回显真实引脚名，不是写死的）② 换 `OLED_ADDR=0x3D` ③ 杜邦线/排针接触 ④ 模块供电是不是 3V3 |

> 通用兜底：`python tools\ota.py serial --sec 20` 看串口日志；`/log` 里的「本次自检」五项（显示屏/总线/按键/配置/网络）哪一项是 ✗ 一目了然。

## 7. 自检端点怎么用

> 下面的例子一律用 **`curl http://<板子的IP>/...`** —— 板子 IP 看串口日志（`[BOOT] … http://<板子的IP>/`）或 `python tools\ota.py find`。

### 7.1 `/i2c` —— 扫 I2C 总线

```bash
curl http://<板子的IP>/i2c
```

看什么字段：

| 字段 | 含义 |
|---|---|
| `sda` / `scl` | **回显真实引脚名**（走适配层，改了 `config.h` 这里跟着变） |
| `found` | 扫到的地址列表，OLED 正常应出现 `"0x3c"` |
| `count` | 扫到几个（正常 1） |

- 扫到 `0x3c` 但不亮 ⇒ 试 `OLED_ADDR 0x3D`。
- 扫不到 ⇒ 接线 / 共地 / 模块供电问题（不是固件问题）。

### 7.2 `/tjcwire` —— 串口屏线路体检（D5–D7 短接）

```bash
curl http://<板子的IP>/tjcwire
```

- 做法：**先把 D5 与 D7 用杜邦线短接**，端点会在 D7 打 **200 个方波**、用中断数 D5 上的边沿（`rom-watch.ino:1919`）。
- 看什么字段：`edges`（实测边沿数）、`expect`（= **400**）、`verdict`（人话结论）。
  - `edges > 50` ⇒ **两个脚 + 杜邦线都通** ✓（这时屏还不回话 ⇒ 问题在屏 / 屏的供电 / 接反）
  - 只有零星边沿 ⇒ 接触不良或线太长
  - `0` ⇒ ① D5–D7 没短接 ② 或这两个脚/线有问题

> ⚠️ 为什么不能「自己发自己收」：Arduino SoftwareSerial 在**发送期间会关掉自己的接收中断**（半双工）⇒ 自收自发必然是 0 字节，测不出东西。

### 7.3 `/tjcsweep` —— 逐档试屏的波特率

```bash
curl http://<板子的IP>/tjcsweep
```

- 依次试 `9600 / 115200 / 19200 / 38400 / 57600 / 4800 / 2400 / 230400`，每档发 `connect`，看屏回不回 `comok`。
- 看什么字段：`try[].baud` / `try[].len`（回包长度）/ `try[].resp`（回包十六进制）/ `try[].OK`（是否命中）、`hit`（命中的那档）、`restored`（**恒为 115200**）。
- ★扫完会把串口**复位成 115200**（`rom-watch.ino:1957-1961`）—— 不复位的话屏那头会看到乱码，表现为「屏突然再也不动了」。

### 7.4 `/rom` —— 状态 JSON（自检主视图）

```bash
curl http://<板子的IP>/rom
```

排错最常看的字段：

| 字段 | 看什么 |
|---|---|
| `tjcEn` | 本固件**有没有编**串口屏（`USE_TJC`）；false ⇒ 后面 `tjcOk` 一定是 false，不是屏坏 |
| `tjcOk` / `tjcBaud` / `tjcInfo` | 屏答没答话 / 探到的波特率 / 屏的 `connect` 回包（十六进制） |
| `led` / `ledPin` / `ledAlarm` / `ledForce` / `otaRunning` | `led` 是**回读引脚真实电平**；`ledAlarm` 是「逻辑要不要亮」⇒ 两者一比就知道是灯坏还是逻辑不对 |
| `cur` | 本次自检：`oled` / `i2c` / `btn` / `cfg` / `net` 五项 |
| `bb` | 黑匣子：`boots`（启动次数）/ `reset`（上次复位原因）/ `phaseLast` + `phaseLastTxt`（上次崩在哪一步）/ `wifiMs` |
| `scrMin` / `scrUp` | 屏上画的是第几分钟 / 上次重画距今几秒（正常 `scrUp < 60`） |
| `lastBody` | 「调试：最近响应片段」—— 数据源抓取失败时先看它 |
| `waitS` / `nextIn` | 下次检查间隔 / 还有多少秒 |
| `preset` / `presetName` / `jsonKey` / `timeKey` | 当前在盯哪个源、用什么键解析 |

### 7.5 `/log` —— 纯文本日志（一眼看）

```bash
curl http://<板子的IP>/log
```

一行一个字段，重点：

- `启动次数` / `上次复位原因` / `上次跑到阶段` —— 反复重启时看这三行。**阶段 0 = 刚升级/首次上电**（RTC 记忆被清），不是崩溃。
- `上次自检` / `本次自检` —— 显示屏 / 总线 / 按键 / 配置 / 网络。
- `连续失败` + `原因` —— 数据源抓取失败的直接原因。
- `编译开关` —— `USE_TJC=… USE_OLED=…`（确认烧进去的固件是哪个配置）。
- `堆内存` / `信号` / `固件` —— 版本与资源余量。
